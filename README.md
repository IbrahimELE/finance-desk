# Finance Desk for Möbius

The Finance Desk (repo root) packaged as a Möbius mini-app: AI research briefs from live Yahoo Finance data and the
latest 10-K risk section, live charts, paper trading with $100,000 of virtual money, a workspace leaderboard
(day / week / month, permanent medals) and briefs that adapt to your ratings.

## How it maps onto Möbius
| Web app (run.sh)                     | Möbius package                                               |
|--------------------------------------|--------------------------------------------------------------|
| `frontend/index.html`                | `ui_css.js`, `ui_markup.js`, `ui_desk.js`, generated by `port_ui.py` |
| `agent_service` (HTTP + LLM)         | `service.py` + `fd_desk.py`; the AI thesis comes from the owner's own Möbius AI (`runtime.js`) |
| `data_service/app`, `learning_service/app` | `fd_data/`, `fd_learning/`, copied by `sync.sh` (same code) |
| localStorage, browser notifications  | the app's Möbius storage (`ui-state.json`), Möbius push notifications |

A Möbius service request may run for 15 seconds, an AI answer takes longer, so the service returns the data and a
template brief, and the app asks the AI through a hidden app chat with whichever model the owner uses. Without AI
the template brief is kept. Learning uses its rules (the optional LLM summary is off).

## Build and install locally
```
mobius/sync.sh /data/apps/finance-desk     # regenerate the UI + copy modules, then copy the package there
```
Then apply `/data/apps/finance-desk` in Möbius. Recompile `requirements.lock` after changing `requirements.in`:
`pip-compile --generate-hashes --strip-extras requirements.in -o requirements.lock`.

Never edit `fd_data/`, `fd_learning/`, `ui_*.js` or `vendor/` by hand: change the source and run `sync.sh`.

## Data and privacy
Everything stays in the owner's Möbius (app storage): workspaces, briefs, paper accounts, ratings, UI state.
Market data comes from Yahoo Finance and SEC EDGAR. Research and learning tool, not investment advice.

## Global competition (all Möbius players)
One host instance (`fd_compete.HOST_DEFAULT`, currently `mobius-production-ddf2.up.railway.app`) keeps one
$100,000 competition account per Möbius @handle, separate from the player's private workspaces. Players send only
orders; the host fills them at its own prices and ranks the accounts it keeps (same day/week/month rules and
permanent medals as the local leaderboard; competition accounts have no reset).

Identity uses the official Hackaton 2026 protocol: the player's instance stores a 2-minute proof (digest of the exact
request, @handle, target host) and sends its key; the host fetches it back from the sender, which must be a host the
Möbius identity directory lists for that @handle. Writes are replay-safe per player and request id. Public routes:
`GET proof/<key>` (player side) and `POST exchange` (host side); everything else needs the owner's app token.
Requirements for a player: an online Möbius registered to their @handle (managed Railway deployments are).
`fd_fed/` holds the platform's SSRF-safe federation transport (MIT), unchanged except a local `HTTPException`.
Note: Möbius runs one app's public requests one at a time, so the host's own owner plays locally, never via exchange.
